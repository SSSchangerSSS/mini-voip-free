# Mini VoIP Free — تلفن داخلی اندروید

تماس صوتی دونفره بین کاربران با شماره داخلی، نام و رمز؛ با سرور خودتان، پنل مدیریت وب و دفترچه مشترک. نسخه Android برای دریافت مستقیم تماس به **حساب Google، Firebase و Google Play services نیاز ندارد**. ارتباط کنترل و SIP از HTTPS/WSS و صوت از RTP استفاده می‌کند.

> نسخه فعلی نامزد تست دستی است؛ انتشار تولیدی تأییدشده نیست. دامنه اصلی Android8–15 است؛ تست نمونه‌ها و محدودیت‌های واقعی در [گزارش‌ها](qa/reports) ثبت شده‌اند. کاربر عملکرد نسخه قبلی را روی دو گوشی تأیید کرده است؛ این تأیید جای آزمون همه مدل‌ها یا نسخه جدید را نمی‌گیرد. مسیر iOS هنوز به گیت‌های دستگاه و Apple وابسته است.

## از کجا شروع کنم؟

| نقش | مسیر کوتاه |
|---|---|
| کاربر گوشی | APK ارائه‌شده توسط مدیر را نصب کنید ← شماره/رمز ← آیکون زنگ و راه‌اندازی دریافت ← دفترچه و تماس |
| مدیر همین سیستم آزمایشی | [پنل محلی](http://127.0.0.1:5080/admin)؛ فایل رمز مدیر: `deploy/secrets/admin-password` |
| نصب روی سرور تازه | مراحل زیر را به ترتیب اجرا کنید؛ سپس APK متناسب با گواهی سرور بسازید |
| راهنمای آزمون گوشی | [آزمون دو گوشی](docs/PHONE_RC_TEST.fa.md) و [نکات HyperOS](docs/POCO_HYPEROS.fa.md) |

آدرس `192.168.1.151` در مثال‌ها مربوط به شبکه آزمایش است؛ روی شبکه خودتان آدرس ثابت و آزاد سرور را جایگزین کنید. صفحه دریافت موقت این سیستم [اینجاست](http://192.168.1.151:8765/)؛ این آدرس، لینک عمومی دانلود برای دیگران نیست. APK داخل Git نگه‌داری نمی‌شود.

## ۱. پیش‌نیاز سرور

- Linux x86_64 (محیط آزموده‌شده) با Docker Engine و Compose v2، Git و Python3؛ کاربر اجرا باید دسترسی Docker داشته باشد.
- آی‌پی ثابت یا رزرو DHCP روی روتر؛ گوشی‌ها باید سرور را ببینند. برای شروع، سرور و دو گوشی روی یک LAN/Wi-Fi باشند.
- TCP443 برای HTTPS/WSS و UDP10000–10199 برای صوت؛ در حالت گواهی عمومی، TCP80 نیز لازم است. پورت‌های داخلی5038/5080/8088/5060 را به اینترنت باز نکنید.
- نسخه‌های ابزار و imageها در [toolchain.lock.json](toolchain.lock.json) قفل شده‌اند؛ نسخه‌ها را خودسرانه ارتقا ندهید.

```bash
git clone https://github.com/SSSchangerSSS/mini-voip-free.git
cd mini-voip-free
cp deploy/site.env.example deploy/site.env
./smi server configure --host 192.168.1.151 --tls internal
```

`configure` آدرس اعلان‌شده API، WSS و مرکز تلفن را تنظیم می‌کند؛ **IP کارت شبکه را تغییر نمی‌دهد**. آدرس باید از قبل به میزبان تخصیص یافته یا از طریق شبکه به آن هدایت شده باشد. فایل env را برای نیازهای دیگر بررسی کنید؛ هیچ رمز واقعی در آن نگذارید.

## ۲. ساخت رمزهای خصوصی و اجرای سرور

این دستور فقط فایل‌های مفقود را می‌سازد؛ مقدار رمزها چاپ نمی‌شود و فایل موجود تغییر نمی‌کند:

```bash
python3 - <<'PY'
from pathlib import Path
import os, secrets
folder = Path('deploy/secrets')
folder.mkdir(parents=True, exist_ok=True)
for name in ('ami', 'admin-password', 'developer-password'):
    path = folder / name
    if not path.exists():
        fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
        with os.fdopen(fd, 'w') as out:
            out.write(secrets.token_urlsafe(24) + '\n')
PY
./smi server init --config deploy/site.env
./server start
./server status
```

`start` مالکیت پوشه‌های runtime را برای سرویس UID1001 آماده می‌کند؛ فایل‌های رمز runtime فقط برای مالک و گروه سرویس خواندنی می‌شوند(mode640). رمز دولوپر که وارد build می‌شود همچنان600می‌ماند؛ هیچ دسترسی world-readable داده نمی‌شود.

`init` برای میزبان تازه است؛ اگر پورت‌های سرور در حال اجرا اشغال‌اند، آن را دوباره اجرا نکنید. `start` فایل‌ها و دیتای موجود را نگه می‌دارد. موفقیت واقعی را از `/health/ready` با200 و وضعیت سرویس‌ها بررسی کنید. نبود تنظیمات/سرویس، دلیل BLOCKED/خطا دارد؛ exit0 جعلی نیست.

فرمان‌های روزمره:

```bash
./server start                       # اجرای stack موجود یا اعمال config
./server status                      # سلامت Control/PBX/Edge
./server logs                        # لاگ Control؛ رمز/لاگ خام را منتشر نکنید
./smi server up --config deploy/site.env
```

### TLS در LAN و اینترنت

در حالت `internal`، Caddy گواهی را با CA خصوصی همین سرور صادر می‌کند. برای ساخت APK، **فقط گواهی عمومی ریشه** را استخراج کنید:

```bash
mkdir -p .tool-results
# پس از اولین start و صدور CA:
docker cp smi-edge:/data/caddy/pki/authorities/local/root.crt .tool-results/server-root.crt
```

کلید خصوصی CA، دیتابیس و `deploy/secrets/` را به گوشی یا Git نفرستید. مرورگر پنل روی LAN نیز باید به همین CA اعتماد کند؛ برای مدیریت روی خود سرور، loopback `http://127.0.0.1:5080/admin` موجود است.

برای دامنه عمومی، DNS را به IP ثابت سرور هدایت، `SMI_ACME_EMAIL` را در env تنظیم و اجرا کنید:

```bash
./smi server configure --host phone.company.com --tls public
./server start
```

این مثال دامنه فرضی است؛ دامنه تحت کنترل خودتان را وارد کنید. شبکه بیرونی/NAT/فایروال و صوت باید جداگانه آزموده شوند. نصب روی شبکه عمومی با مثال LAN به‌تنهایی تأیید نمی‌شود. روی سرور موجود، تغییر host همان CA داخلی را نگه می‌دارد؛ روی سرور تازه، CA دیگری ایجاد می‌شود.

## ۳. پنل وب و مدیریت کاربران

روی خود سرور: `http://127.0.0.1:5080/admin`؛ از دستگاه دیگر: `https://<server>/admin`. رمز مدیر را از فایل خصوصی `deploy/secrets/admin-password` در ویرایشگر محلی بخوانید. در چت، screenshot یا Git منتشر نکنید.

- **ساخت داخلی:** شماره101تا199، نام نمایشی و رمز حداقل12نویسه؛ حداکثر30داخلی فعال.
- **فهرست و فیلتر:** جست‌وجوی نام/شماره و فیلتر فعال، غیرفعال، دستگاه متصل یا بدون دستگاه.
- **ویرایش:** نام و رمز؛ خالی‌گذاشتن رمز هنگام ویرایش، رمز قبلی را حفظ می‌کند. شماره شناسه حساب است؛ برای شماره جدید حساب جدید بسازید.
- **اجبار ورود مجدد:** نشست‌ها و اتصال دستگاه قبلی باطل می‌شوند؛ کاربر باید دوباره شماره/رمز را وارد کند. رمز فعلی عوض نمی‌شود.
- **تغییر رمز:** نشست‌ها و اعتبار SIP قبلی باطل می‌شوند؛ ورود بعدی با رمز جدید است.
- **غیرفعال‌کردن:** ورود و تماس حساب متوقف و حساب از دفترچه کاربران حذف می‌شود؛ قابل فعال‌کردن دوباره است.
- **حذف داخلی:** از پنل جاری، دفترچه و PBX حذف و نشست‌ها باطل می‌شوند؛ رکورد تاریخی برای حفظ سوابق باقی می‌ماند. ساخت دوباره همان شماره ممکن است و نشست قبلی را احیا نمی‌کند.

عملیات حساس روی حساب دارای تماس فعال رد می‌شود؛ ابتدا تماس را تمام کنید. رمزها در فهرست نمایش داده نمی‌شوند. اگر پیام `RELOAD_PENDING` دیدید، ثبت DB انجام شده ولی اعمال PBX هنوز تأیید نشده؛ وضعیت سرور را بررسی کنید. فقط پیام APPLIED را تأیید اعمال مرکز تلفن بدانید.

## ۴. ساخت APK و نصب روی گوشی

برای ساخت محلی، Flutter/Dart، JDK17 و AndroidSDK مطابق lock لازم‌اند. overlay بومی و SDK محلی را حفظ کنید:

```bash
# اگر پوشه android در checkout موجود است، flutter create لازم نیست.
./scripts/build/apply-platform-overlay.sh
./smi build android --release \
  --server-host 192.168.1.151 \
  --trusted-ca-file .tool-results/server-root.crt \
  --developer-password-file deploy/secrets/developer-password
```

برای سرور عمومی با زنجیره مورد اعتماد، گزینه `--trusted-ca-file` لازم نیست. خروجی: `apps/mobile/build/app/outputs/flutter-apk/app-release.apk`. ساخت بدون `--developer-password-file`، تغییر آدرس با رمز دولوپر را غیرفعال می‌کند. فایل رمز باید private/mode600 و12تا256بایت باشد.

در این checkout، وابستگی‌های Flutter و Gradle از میرورهای پیکربندی‌شده دریافت می‌شوند؛ مسیرهای نصب مخصوص این PC پیش‌نیاز عمومی نیستند. امضای فعلی آزمایشی است؛ قبل از انتشار واقعی signing سازمانی و گیت‌های انتشار لازم‌اند. برای Update باید امضای APK با نصب قبلی یکسان باشد.

APK را از مسیر مورد اعتماد مدیر دریافت و روی هر دو گوشی نصب کنید؛ هنگام ارتقا اپ را حذف نکنید. شماره و رمز هر گوشی باید متفاوت باشد. پس از ورود:

1. آیکون زنگ ← «راه‌اندازی دریافت تماس» ← «ادامه: مرحله بعد».
2. میکروفن/اعلان را در پنجره Android تأیید کنید؛ باتری و نمایش تمام‌صفحه را در تنظیمات سیستم فعال کنید.
3. به اپ برگردید تا وضعیت واقعی دوباره خوانده شود؛ بازشدن تنظیمات به معنی فعال‌شدن نیست.
4. در Poco/Xiaomi/Redmi، بخش HyperOS را بررسی کنید. اگر مسیر اختصاصی موجود نباشد، اطلاعات برنامه و پیام راهنما باز می‌شود. وضعیت autostart اختصاصی قابل تأیید خودکار نیست.
5. از آیکون مخاطبین، نام و شماره کاربران فعال را ببینید؛ روی کاربر دیگر بزنید یا شماره را بگیرید. نام/شماره تماس‌گیرنده نمایش داده می‌شود.

### تغییر IP در خود اپ

در صفحه ورود یا شماره‌گیر، **آیکون تنظیمات ← تنظیمات سرور** را باز کنید. آدرس `host` یا `host:port` را بدون `http` و مسیر وارد و رمز دولوپر همین build را بزنید. رمز در فایل خصوصی `deploy/secrets/developer-password` روی سیستم سازنده APK است؛ تغییر فایل پس از ساخت، رمز APK قبلی را تغییر نمی‌دهد.

پس از ذخیره، حساب قبلی خارج می‌شود؛ اطلاعات ورود سرور جدید را وارد کنید. آدرس در ذخیره امن گوشی می‌ماند. گواهی سرور جدید باید هم برای آدرس جدید معتبر و هم مورد اعتماد APK باشد؛ قفل دولوپر، TLS یا احراز هویت سرور را دور نمی‌زند. برای CA جدید باید APK متناسب با CA بسازید؛ صرف تغییرIP کافی نیست.

## ۵. مخاطبین و نشست‌ها چگونه به‌روز می‌شوند؟

هر اپ واردشده یک long-poll احرازشده به سرور دارد. تغییرات پنل پس از ذخیره فوراً سیگنال می‌دهند؛ به بازکردن دوباره دفترچه یا refresh دستی نیاز نیست. snapshot و hash مشترک از خواندن‌های تکراری DB جلوگیری می‌کنند. تغییرات بیرون پنل/CLI حداکثر5ثانیه بررسی می‌شوند. در قطع شبکه یا توقف اپ توسط سیستم، دریافت تا برقراری دوباره اتصال به تأخیر می‌افتد؛ دسترسی آفلاین/دریافت تضمینی ادعا نمی‌شود.

با ابطال نشست، نسخه جدید اپ اعتبارنامه و دفترچه محلی را پاک می‌کند و ورود دستی می‌خواهد؛ در شروع سرد نیز توکن ذخیره‌شده قبل از ورود خودکار بررسی می‌شود. گوشی آفلاین تا تماس بعدی با سرور نمی‌تواند از ابطال مطلع شود.

## ۶. آزمون سریع و عیب‌یابی

- گوشیA وB با دو داخلی متفاوت وارد شوند؛ تماس دوطرفه، نام، شماره و صوت دوطرفه را بررسی کنید.
- قبل از لمس بلندگو، مسیر صدای گوشی را امتحان کنید؛ سپس روشن/خاموش کنید. پس از پاسخ زنگ باید قطع شود.
- Home، برنامه دیگر، کنارزدن کارت Recent، قفل1دقیقه و30دقیقه و restart را جداگانه آزمایش کنید.
- نام کاربر آزمایشی را در پنل تغییر دهید؛ دفترچه باز هر دو گوشی باید خودکار عوض شود. سپس اجبار ورود، تغییر رمز و حذف را روی **حساب آزمایشی** امتحان کنید.

| مشکل | بررسی |
|---|---|
| ورود ممکن نیست | سرور ready200، مسیر شبکه، آدرس و اعتماد گواهی؛ رمز/شماره و وضعیت enabled |
| «دستگاه دیگری فعال است» | مدیر ← اجبار ورود مجدد؛ سپس ورود روی گوشی موردنظر |
| صدا یک‌طرفه/قطع است | UDP/RTP، firewall/NAT و مسیر شبکه؛ فقط بازشدن پنل، تأیید صوت نیست |
| پس از بستن اپ زنگ نمی‌خورد | اعلان آماده‌باش، مجوزهای داخل اپ و محدودیت‌های سازنده؛ [HyperOS](docs/POCO_HYPEROS.fa.md) |
| تنظیمات سرور ذخیره نمی‌شود | رمز دولوپر همانAPK، نبود تماس فعال و آدرس معتبر؛ پس از5خطا یک دقیقه صبر کنید |
| TLS بعد از تغییرIP خطا دارد | SANگواهی، CAهمانسرور و ساختAPKباCAدرست؛ بررسیTLSراخاموش نکنید |

Force stop در تنظیمات یا Stop سیستم دریافت را متوقف می‌کند؛ اپ را دوباره باز کنید. بعد از نصب اولیه هم اولین ورود/راه‌اندازی لازم است. سرور و شبکه باید روشن و در دسترس بمانند؛ محدودیت‌های OEM و باتری روی تمام گوشی‌ها یکسان نیستند.

### جابه‌جایی IP همان سرور و همان دیتابیس

اگر آدرس همان سرور را عوض می‌کنید، بهتر است تنظیم آدرس گوشی‌ها را زمانی ذخیره کنید که آدرس قبلی هنوز در دسترس است؛ خروج قبلی در این حالت می‌تواند ثبت دستگاه را آزاد کند. سپس آدرس ثابت/شبکه و config سرور را اعمال و با آدرس جدید وارد شوید. اگر آدرس قبلی از قبل قطع شده و «دستگاه دیگری فعال است» دیدید، مدیر از پنل سرور جدید برای همان داخلی «اجبار ورود مجدد» را بزند. این مرحله رمز کاربر را عوض نمی‌کند.

فیلتر «دستگاه متصل» در پنل، ثبت حساب روی دستگاه را نشان می‌دهد؛ تضمین آنلاین‌بودن لحظه‌ای گوشی نیست.
