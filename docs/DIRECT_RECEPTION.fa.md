# دریافت تماس بدون حساب Google

> نسخه 0.3.0+29 نامزد تست دستی است. گیت لاگ SDK رویAPI26/35 با تماس واقعی PASS شده؛ صدای فیزیکی، قفل طولانی و رفتار سازندگان هنوز نیازمند آزمون گوشی هستند. راهنمای آزمون: [دو گوشی](PHONE_RC_TEST.fa.md).

نسخه Android ‎0.3.0+29 به Firebase، حساب Google، Google Play services یا اینترنت عمومی نیاز ندارد. گوشی باید به شبکه‌ای وصل باشد که سرور `192.168.1.151` را می‌بیند. صوت و پیام تماس هر دو روی سرور خودتان هستند.

1. APK جدید را روی نسخه قبلی نصب کنید؛ برنامه را حذف نکنید تا حساب ذخیره‌شده بماند. یک بار باز کنید و اجازه اعلان و میکروفون بدهید. نصب اولیه بدون ورود حساب نمی‌تواند تماس دریافت کند.
2. آیکون زنگ بالای شماره‌گیر را بزنید. اگر درخواست معافیت مصرف باتری آمد، برای Mini VoIP اجازه دهید. آماده‌باش دائمی برای تماس، نسبت به push ابری باتری بیشتری مصرف می‌کند.
3. دوباره آیکون زنگ را بزنید؛ در Android14+ اگر اجازه نمایش تمام‌صفحه تماس درخواست شد آن را فعال کنید. تنظیمات اعلان تماس نیز باید صدادار و روی صفحه قفل مجاز باشد.
4. در تنظیمات سازنده گوشی، Battery → Unrestricted / No restrictions و در صورت وجود Auto start را برای اپ فعال کنید. نام منو در Samsung/Xiaomi/Huawei متفاوت است.
5. اعلان دائمی «تماس داخلی · اتصال مستقیم» باید پس از ثبت SIP عبارت «آماده دریافت تماس از سرور شرکت» نشان دهد. این اعلان با بستن صفحه اپ باقی می‌ماند؛ هیچ میکروفونی در حالت آماده‌باش باز نیست.

ابتدا هر دو اپ باز و تماس دوطرفه برقرار شود. سپس برای هر گوشی جدا، از گوشی دوم در حالت Home، اپ دیگر، قفل چنددقیقه‌ای، حذف از Recent apps، و بعد از خاموش/روشن‌کردن گوشی و بازشدن اولیه قفل تماس بگیرید. زنگ، نام+داخلی، پاسخ، صدای گوشی/بلندگو، میوت، رد و لغو را بررسی کنید. برای اثبات نبود وابستگی ابری، می‌توان اینترنت روتر را قطع کرد ولی Wi-Fi و دسترسی شبکه داخلی به کامپیوتر حفظ شود.

پس از قطع/وصل Wi-Fi یا سرور، اعلان باید دوباره آماده شود؛ بازیابی اتصال ممکن است چند ده ثانیه طول بکشد. تا آماده‌شدن واقعی، تماس را موفق معرفی نکنید.

«Force stop / توقف اجباری» در تنظیمات یا Stop در مدیریت سرویس‌های فعال سیستم می‌تواند دریافت را متوقف کند؛ اپ را دوباره باز کنید. پاک‌کردن داده/حذف اپ نیز حساب را از بین می‌برد. حذف از Recent با Force stop یکسان نیست. هیچ تضمین صفرخطا درباره همه سازندگان و نسخه‌های میانی Android داده نشده است؛ آزمون همان گوشی لازم است.

راهنمای پروژه Firebase مربوط به مسیر کنارگذاشته‌شده است و برای این نسخه کاربرد ندارد. راهنمای مدیریت و اجرای سرور: [ADMIN_SERVER.fa.md](ADMIN_SERVER.fa.md).

## دامنه عمومی Android8 تا15

مدل گوشی شرط نصب یا پیاده‌سازی نیست. minSdk26 است و مسیرها با نسخه سیستم انتخاب می‌شوند:

| نسخه | مسیر سازگاری |
|---|---|
| Android8 / API26–27 | ConnectionService خودمدیریت‌شده از Core-Telecom، NotificationChannel و نمایش قفل با API/flags متناسب |
| Android9–11 | همان مسیر، و نوع phoneCall فقط از API29 به بالا |
| Android12–12L | PendingIntent تغییرناپذیر و اجزای بومی غیرعمومی؛ شروع آماده‌باش از اجرای مجاز اپ/سیستم |
| Android13 | اجازه اعلان هنگام اجرا؛ تماس با اجازه و اعلان آماده‌باش قابل مشاهده |
| Android14–15 | specialUse برای آماده‌باش، phoneCall برای تماس، بررسی اجازه تمام‌صفحه و باتری؛ بدون dataSync شش‌ساعته |

این جدول مرور طراحی/guardهای API است، نه مدرک اجرای همه نسخه‌ها یا مدل‌ها. طبق خواسته مالک فقط شبیه‌سازهای8 و15 تهیه شده‌اند؛ اجرای9 تا14 NOT_RUN است. محدودیت‌های سازنده و صدای واقعی باید با آزمون دستی پوشش داده شوند. هیچ API عمومی نمی‌تواند Force stop یا تمام سیاست‌های اختصاصی سازنده را بی‌اثر کند.

نسخه21 چرخه اعلان تماس و task را مطابق تصمیم0016 اصلاح می‌کند. هنگام مکالمه، اعلان تماس جای آماده‌باش را می‌گیرد و پس از پایان، آماده‌باش برمی‌گردد. گزارش جاری: [اصلاح دو ایراد](../qa/reports/2026-11-01-background-ringing/REPORT.fa.md).

نسخه24 راه‌اندازی مرحله‌ای مجوزها را اضافه می‌کند؛ راهنمای فعلی در [آزمون گوشی](PHONE_RC_TEST.fa.md) است. مجوزهای استاندارد دوباره خوانده می‌شوند؛ autostart اختصاصی HyperOS تأییدنشده است. این تغییر، رفع قطعی توقف سرویس روی Poco را اثبات نمی‌کند.
