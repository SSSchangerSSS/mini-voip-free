# تست همین نسخه روی دو گوشی اندرویدی — 2026-10-31

نسخه نصب: **0.1.1+4**؛ سرور `192.168.1.151`. هر دو گوشی به Wi-Fi همان شبکه کامپیوتر متصل باشند؛ کامپیوتر و سرور روشن بمانند. این مسیر برای تست محلی است. داخلی‌های104 و105 مخصوص این دو گوشی آماده شده‌اند؛101 و103 برای شبیه‌سازها حفظ شده‌اند.

## دریافت و ورود

1. در مرورگر هر گوشی `http://192.168.1.151:8765/` را دقیقاً با http باز و APK را دریافت کنید. صفحه دانلود موقت است و فقط همین APK/اطلاعات عمومی را ارائه می‌کند؛ رمزها روی آن نیستند. از سمت کامپیوتر پاسخ HTTP بررسی شد و کاربر نیز بازشدن صفحه روی یکی از گوشی‌ها را تأیید کرد.
2. APK را باز و مجوز نصب از همین مرورگر/فایل‌منیجر را در صورت درخواست بدهید. این APK آزمایشی با کلید محلی امضا شده است. سپس Mini VoIP Free را باز کنید.
3. سرور داخل APK از قبل151 تنظیم شده است؛ CA خصوصی همین سرور داخل اپ مورد اعتماد است و برای این فایل نصب نیازی به نصب CA در تنظیمات گوشی یا خاموش‌کردن اعتبارسنجی TLS نیست.
4. گوشی اول با104 و گوشی دوم با105 وارد شوند. رمزهای جداگانه در فایل خصوصی `deploy/secrets/phone-test-accounts.txt` روی کامپیوتر هستند؛ فایل در ویرایشگر متن محلی باز شده است. رمزها را وارد چت/Git یا صفحه دانلود نکنید. هر داخلی به یک نصب فعال متصل می‌شود.
5. مجوز میکروفون را بدهید و منتظر «آماده» بمانید. هشدار غیرفعال‌بودن اعلان پس‌زمینه در این بیلد واقعی است.

اگر صفحه دریافت باز نشد: آدرس را با http بررسی کنید، اینترنت سیم‌کارت/VPN را برای همین تست کنار بگذارید و از Wi-Fi اصلی همان شبکه استفاده کنید؛ Guest Wi-Fi یا جداسازی کاربران مودم ممکن است دسترسی به کامپیوتر را ببندد. خطای دقیق را گزارش کنید؛ داده اپ یا حساب‌ها را برای رفع خطای شبکه پاک نکنید. راه جایگزین انتقال APK از فایل محلی `artifacts/android/mini-voip-free-0.1.1+4-lan.apk` با USB است. دریافت فایل به معنی صحت مسیر صوت نیست؛ تماس مرحله بعد آن را می‌آزماید.

## اولین تماس و آزمون صوت واقعی

هر دو اپ باز و صفحه هر دو روشن بماند. گوشی‌ها کمی از هم فاصله داشته باشند تا صدای محیط بازخورد ایجاد نکند. در104 مقصد105 را بگیرید و روی105 پاسخ دهید. هر نفر جداگانه صحبت کند و شنیده‌شدن صدا در جهت مقابل را تأیید کنید. تماس را دو دقیقه نگه دارید؛ میوت را روشن کنید و بررسی کنید صدای ارسال‌شده قطع و پس از خاموش‌کردن بازگردد. بلندگو/گوشی را عوض کنید و از هر دو سمت قطع را امتحان کنید. جهت را105→104 عوض کنید؛ سپس رد تماس، لغو قبل از پاسخ و بی‌پاسخی حدود40ثانیه را بررسی کنید.

پس از هر مرحله، هر دو اپ باید به شماره‌گیری برگردند و تماس بعدی ممکن باشد. Home/بستن و بازکردن اپ و حفظ حساب را جدا بررسی کنید. **دریافت تماس وقتی اپ بسته، در پس‌زمینه یا صفحه قفل است هنوز پشتیبانی تأییدشده این تحویل نیست**؛ صرف حضور در Recent Apps کافی نیست. Push تنظیم نشده است. نتیجه گوشی واقعی تا قبل از اجرای واقعی شما PASS اعلام نمی‌شود.

## مدیریت داخلی‌ها روی همین کامپیوتر

پنل مدیریت گرافیکی/وب در این نسخه وجود ندارد؛ شناسه ورود همان شماره داخلی سه‌رقمی101..199 است. مدیریت با CLI سرور است؛ فایل‌ها/پایگاه‌داده را دستی ویرایش نکنید. در ترمینال:

```bash
cd /home/changer/Desktop/flash/mini-voip-free
./smi server status
```

برای ساخت **شماره آزاد جدید** مثلاً106، رمز تصادفی فقط در فایل خصوصی تولید کنید:

```bash
umask 077
openssl rand -hex 12 > deploy/secrets/phone-106.credential
./smi extension add 106 --credential-file deploy/secrets/phone-106.credential
docker exec smi-pbx asterisk -rx 'module reload res_pjsip.so'
```

قبل از انتخاب شماره، فهرست endpointهای فعال را ببینید:

```bash
docker exec smi-pbx asterisk -rx 'pjsip show endpoints'
```

`Unavailable` برای حسابی که هنوز گوشی با آن وارد نشده، به‌تنهایی خطای ساخت حساب نیست. تماس‌های جاری:

```bash
docker exec smi-pbx asterisk -rx 'core show channels'
```

غیرفعال‌کردن یک داخلی (مثال106؛ روی حساب در حال استفاده اجرا نکنید):

```bash
./smi extension disable 106
docker exec smi-pbx asterisk -rx 'module reload res_pjsip.so'
```

انتقال104 به گوشی دیگر/نصب دوباره، در حالت بدون تماس:

```bash
./smi device reset 104 --credential-file deploy/secrets/phone-104.credential
docker exec smi-pbx asterisk -rx 'module reload res_pjsip.so'
```

reset نشست‌های قبلی را باطل، اتصال دستگاه را آزاد و رمز SIP را می‌چرخاند؛ **رمز ورود حساب را عوض نمی‌کند**. روی گوشی جدید با همان رمز104 وارد شوید. `extension add` روی شماره موجود، رمز ورود و SIP آن را تغییر و حساب را فعال می‌کند؛ آن را با ساخت شماره تازه اشتباه نگیرید. برای تعویض رمز حساب موجود باید رمز جدید در فایل خصوصی قرار گیرد و نشست/دستگاه قبلی نیز با reset باطل شود؛ ابتدا نبود تماس را بررسی کنید.

فعلاً اگر CLI پیام `PJSIP_RELOAD_PENDING` داد، اعمال تغییر کامل تأیید نشده است؛ فرمان reload بالا را اجرا و وجود endpoint را جدا بررسی کنید. پیام قدیمی CLI درباره retry روی reconnect، جای این بررسی واقعی را نمی‌گیرد. کاربر فعلی عضو docker است؛ اگر ترمینال دیگری Permission denied داد، همان متن خطا را گزارش کنید.
