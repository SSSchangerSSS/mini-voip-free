# راهنمای کامل استفاده — mini-voip-free

> این سند دقیقاً می‌گوید چطور از تحویل‌دادنی‌ها استفاده کنید: **سرور** را روی یک VPS بالا بیاورید، از GitHub Actions **APK اندروید** با آدرس سرور خودتان بگیرید، و دو داخلی را به هم وصل کنید.
> قاعده صداقت پروژه (AGENTS.md قاعده ۱) در کل این سند برقرار است: هر چیزی که هنوز واقعاً تست نشده، صریحاً «تست‌نشده» نوشته شده است.

---

## ۱) چه چیزهایی تحویل داده می‌شود؟

| تحویل‌دادنی | از کجا | وضعیت صادقانه |
|---|---|---|
| **کد کامل سرور + اسکریپت‌های استقرار** | آرتیفکت `mini-voip-free-server-bundle-r*` در صفحه اجرای workflow — یا فایل zip آماده‌ای که در همین چت به شما داده شده | کد واقعی؛ API کنترل ۴۲/۴۲ تست سبز دارد (CI) |
| **اپ اندروید (APK)** | آرتیفکت `mini-voip-free-android-apk-r*` در صفحه اجرای workflow، بعد از اینکه IP/دامنه سرور را در فرم «Run workflow» وارد کردید | Release APK با کلید **debug** امضا شده (B6 هنوز بسته است)؛ در حالت **بدون Push** ساخته می‌شود چون Firebase پروژه شما هنوز وجود ندارد (B3) — تماس ورودی وقتی اپ باز/در پس‌زمینه‌ی اخیر است کار می‌کند؛ Push پس از B3 اضافه می‌شود |
| **iOS** | workflow فعلی فقط اندروید می‌سازد؛ کد iOS در مخزن هست ولی بیلد iOS به Mac + حساب Apple نیاز دارد (B4/B5) | تحویل در این مرحله = اندروید |

سازوکار «ورودی IP» همان چیزی است که خواستید: در workflow `android-build` یک فرم اجرای دستی وجود دارد با فیلد **`server_ip`** (IP یا دامنه سرور) و فیلد اختیاری **`server_port`** (پیش‌فرض 443). این مقدار با `--dart-define` داخل APK پخته می‌شود؛ کاربرِ موبایل فقط شماره داخلی و رمز را وارد می‌کند و فیلد سرور برایش فقط‌خواندنی نشان داده می‌شود.

---

## ۲) پیش‌نیاز سرور (VPS)

- Ubuntu 22.04 یا 24.04، حداقل ۲ vCPU و **۴ گیگابایت RAM** (بیلد اولیه‌ی Asterisk از سورس در RAM کم ممکن است شکست بخورد؛ اگر ۲ گیگ دارید ابتدا ۲ گیگ swap بسازید: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`)
- **یک دامنه واقعی که به IP سرور A-record شده باشد.** مهم: Let's Encrypt گواهی برای IP خام صادر نمی‌کند و اپ هم (طبق قانون ۱۱.۱ سند) هرگز TLS را دور نمی‌زند. دامنه‌ی رایگان (مثلاً از duckdns.org) کافی است. اگر فقط IP دارید، APK ساخته می‌شود و نصب می‌شود، ولی اتصال TLS تا وقتی گواهی معتبر برای آن IP (یا نصب CA داخلی روی گوشی‌ها) داشته باشید، رد می‌شود.
- پورت‌های فایروال: **TCP 80 و 443** عمومی (ACME + همه‌ی ترافیک اپ)، **UDP 10000 تا 10199** عمومی (RTP صدا)، SSH فقط برای IP مدیریت. پورت‌های 5038/5080/8088/5060 هرگز عمومی نباشند (هر سرویس فقط روی loopback گوش می‌دهد).

## ۳) نصب سرور — یک دستور

```bash
# 1) باندل را روی سرور ببرید (از آرتیفکت GitHub یا فایل پیوست‌شده در چت)
unzip mini-voip-free-server-bundle-r*.zip -d mini-voip-free
cd mini-voip-free

# 2) اگر docker ندارید
curl -fsSL https://get.docker.com | sh

# 3) نصب یک‌مرحله‌ای (تعاملی: دامنه + ایمیل ACME را می‌پرسد)
sudo bash scripts/deploy/install-server.sh
```

اسکریپت نصب دقیقاً این کارها را می‌کند (idempotent است، دوباره اجرا کردنش امن است):

1. بررسی docker/openssl و آزاد بودن پورت‌ها (اگر سرویس دیگری روی پورت باشد، **fail-closed** می‌شود و هیچ‌چیز را نمی‌کشد)
2. ساخت `deploy/site.env` از روی پاسخ‌های شما
3. تولید خودکار رمز AMI در `deploy/secrets/ami` (mode 600، هرگز چاپ نمی‌شود)
4. `./smi server init` — ساخت دایرکتوری‌ها، نصب کانفیگ Asterisk، اعتبارسنجی واقعی Caddyfile با ایمیج `caddy:2.11.7`
5. اصلاح مالکیت volume ها برای یوزر 1001 (کنترل‌پلن در کانتینر non-root اجرا می‌شود)
6. `./smi server up` — بالا آوردن ۳ سرویس: `edge` (Caddy 2.11.7)، `pbx` (Asterisk 22.11.0 از سورس، **بیلد اول ۱۵–۳۰ دقیقه**)، `control` (.NET 10)
7. تا سبز شدن `https://دامنه/health/ready` صبر می‌کند (۶۰ بار × ۳۰ ثانیه)
8. می‌پرسد چند داخلی می‌خواهید و برای هرکدام رمز ۱۶ کاراکتری تولید می‌کند؛ رمزها هم یک‌بار در ترمینال چاپ می‌شوند و هم در `credentials/ext-101.txt` (mode 600) ذخیره می‌شوند

> نکته: ساخت داخلی‌ها بعداً هم ممکن است: `./smi extension add 103 --credential-file /مسیر/فایل-رمز` (رمز هرگز در خط فرمان نمی‌آید). این فرمان روی سرور به‌طور خودکار از CLI داخل ایمیج کنترل استفاده می‌کند و نیازی به نصب .NET روی هاست ندارد.

## ۴) گرفتن APK اندروید از GitHub Actions

1. بروید به: `https://github.com/SSSchangerSSS/mini-voip-free/actions` → workflow **android-build**
2. دکمه **Run workflow** → در فیلد:
   - `server_ip`: دامنه سرور (پیشنهادی) یا IP — همان چیزی که در گام ۲ به دامنه اشاره کردید
   - `server_port`: خالی بگذارید (443)
3. **Run workflow** را بزنید. هر دو جاب اجرا می‌شوند:
   - `Build release APK (server: …)` → حدود ۸–۱۵ دقیقه
   - `Package server code bundle` → چند ثانیه
4. بعد از پایان، داخل صفحه‌ی اجرا (run) پایین بخش **Artifacts** دو فایل می‌بینید:
   - `mini-voip-free-android-apk-r<شماره>` → فایل ZIP را دانلود و از حالت فشرده خارج کنید؛ داخلش `mini-voip-free-<سرور>-r<شماره>.apk` است
   - `mini-voip-free-server-bundle-r<شماره>` → کد کامل سرور

> کیفیت APK: Release، universal (همه‌ی CPUها)، امضای debug — برای نصب مستقیم روی گوشی‌های شرکت مناسب است؛ برای انتشار رسمی/استور باید keystore سازمانی جایگزین شود (B6).

## ۵) نصب و ورود در گوشی

1. فایل APK را به گوشی ببرید و نصب کنید (گزینه‌ی «نصب از منابع ناشناس» را برای مرورگر/فایل‌منیجر فعال کنید)
2. اپ **Mini VoIP Free** را باز کنید — فیلد «سرور» از قبل پرشده و غیرقابل تغییر است
3. شماره داخلی (مثلاً `۱۰۱` — ارقام فارسی هم قبول است) و رمزی که در گام ۳ ساخته شد را وارد کنید → **ورود**
4. مجوز میکروفون را بدهید. اگر اتصال درست باشد به صفحه‌ی شماره‌گیر می‌روید و وضعیت ثبت SIP سبز می‌شود

## ۶) اولین تماس آزمایشی

1. روی دو گوشی (یا گوشی + شبیه‌ساز) با دو داخلی مختلف وارد شوید (مثلاً ۱۰۱ و ۱۰۲)
2. در شماره‌گیر، داخلی مقصد (۳ رقم بین ۱۰۱ تا ۱۹۹) را بزنید → دکمه تماس
3. سمت مقصد اعلان تماس ورودی CallStyle می‌آید → پاسخ → صدا دوطرفه
4. قطع، رد، بی‌پاسخی، اشغال — همه به‌صورت EndReasonهای مشخص به دو طرف نمایش داده می‌شود

> صداقت: این مسیر تماس روی PBX واقعی هنوز **تست نشده** است (P2 نیازمند سرور واقعی است؛ `qa/acceptance-tests.json` T01–T60 همه `NOT_RUN` هستند). بعد از استقرار، نتیجه‌ی واقعی را در همان فایل ثبت کنید — نه حدس.

## ۷) عملیات روزانه

```bash
cd mini-voip-free   # ریشه باندل روی سرور
./smi server status       # وضعیت ۳ کانتینر + آماری از پایگاه‌داده
./smi server logs         # دنبال کردن لاگ‌ها
./smi server backup       # بکاپ کامل داده‌ها (خروجی: deploy/backups/)
./smi server restore --from deploy/backups/<فایل>   # بازگردانی
./smi extension add 104 --credential-file /مسیر/امن
./smi device reset 101 --credential-file /مسیر/امن  # چرخش رمز/خروج دستگاه قبلی
./smi release-roll        # به‌روزرسانی به نسخه جدید کد (بعد از push جدید)
```

- لاگ‌های حساس: رمزها/توکن‌ها در لاگ نمی‌آیند؛ اگر فایل secret ای جایی لو رفت، اول revoke/rotate کنید (بخش ۱۱ سند)
- بکاپ‌ها را خارج از سرور نگه دارید (`./smi server backup` خروجی را رمزنگاری با `AGE_RECIPIENT` هم پشتیبانی می‌کند)

## ۸) محدودیت‌های فعلی — صادقانه

| موضوع | وضعیت | اثر |
|---|---|---|
| Push پس‌زمینه (FCM/APNs) | **BLOCKED** — B2/B3 (کلید APNs اپل و پروژه Firebase شما موجود نیست) | تماس ورودی وقتی اپ کاملاً بسته شده باشد زنگ نمی‌خورد؛ اپ باز یا در ریسنت اپس باشد مشکل نیست |
| امضای Release واقعی | **BLOCKED** — B6 (keystore سازمانی) | APK با کلید debug امضا شده؛ نصب می‌شود ولی برای استور/MDM رسمی نیست |
| iOS | **BLOCKED** — B4/B5 (Mac + حساب Apple) | فقط اندروید تحویل می‌شود؛ کد iOS آماده‌ی بیلد در مخزن هست |
| تماس واقعی دوطرفه روی PBX زنده | **تست‌نشده** — P2 | بعد از نصب سرور، اولین تماس ۱۰۱↔۱۰۲ را بگیرید و نتیجه را ثبت کنید |
| TURN/شبکه‌های سخت | غیرفعال طبق سند ۲.۴ | اگر صدا در شبکه‌های NAT سخت یک‌طرفه شد، این گیت باز می‌شود |

## ۹) عیب‌یابی سریع

- `health/ready` سبز نمی‌شود → `./smi server logs`؛ معمولاً AMI (رمز `deploy/secrets/ami`) یا بالا نیامدن pbx است
- اپ «ورود انجام نشد؛ اتصال سرور را بررسی کنید» → گواهی TLS برای دامنه صادر نشده (پورت 80 بسته است؟) یا دامنه‌ی اشتباه در بیلد
- «این شماره داخلی روی دستگاه دیگری فعال است» → همان داخلی روی گوشی دیگری لاگین است؛ `./smi device reset <داخلی> --credential-file …` و دوباره ورود
- صدای یک‌طرفه/قطع → UDP 10000-10199 در فایروال بسته است
- هنگام بیلد اول Asterisk خطای حافظه → swap اضافه کنید (بخش ۲)

## ۱۰) اجرای سرور روی ویندوز — وضعیت: «سند‌شده ولی تست‌نشده»

> صداقت: این بخش روی ویندوز واقعی **تست نشده است** (این پروژه فقط روی لینوکس اجرا و تأیید شده).
> مسیر پشتیبانی‌شده برای تولید همان VPS لینوکسی است (بخش ۲). ویندوز را برای **ارزیابی/شبکه داخلی** به کار ببرید.

### چرا نatively نه؟

- **Asterisk** اصلاً بیلد بومی ویندوز ندارد (سرویس pbx شماست).
- `deploy/compose.yaml` طبق سند ۲.۳ از **host networking لینوکس** استفاده می‌کند (`network_mode: host` + بایند روی 127.0.0.1) که در Docker Desktop ویندوز معنا ندارد.
- سرویس control (.NET 10) و Caddy روی ویندوز اجرا می‌شوند، ولی به‌تنهایی کافی نیستند — pbx گم می‌شود.

### راه درست روی ویندوز: WSL2 (ابونتو داخل ویندوز)

**شرط‌ها:**

| شرط | توضیح |
|---|---|
| ویندوز ۱۱ ۲۲H2 یا جدیدتر | برای حالت شبکه‌ی `mirrored` (بدون آن، فوروارد **UDP 10000-10199** از ویندوز به WSL عملاً ممکن نیست → صدا قطع می‌شود) |
| دامنه + IP عمومی | دامنه باید به IP **عمومیِ** همان ویندوز اشاره کند؛ اگر پشت NAT خانه/اداره است، روی مودم/روتر فوروارد لازم دارید: TCP 80+443 و UDP 10000-10199 |
| باندل داخل فایل‌سیستم لینوکسی | باندل را در `~/` داخل WSL باز کنید، **هرگز** در `C:\` یا `/mnt/c/...` — به همین دلیل `install-server.sh` حالا روی فایل‌سیستم‌های NTFS/drvfs **fail-closed** می‌شود (chmod 600 آنجا واقعاً محافظت نمی‌کند) |

**گام‌ها (PowerShell با دسترسی Administrator):**

```powershell
wsl --install -d Ubuntu-24.04
# بعد از ری‌استارت، فایل %UserProfile%\.wslconfig بسازید:
#   [wsl2]
#   networkingMode=mirrored
# سپس:  wsl --shutdown   و دوباره وارد Ubuntu شوید
```

```powershell
# فایروال ویندوز (هر ۳ قانون)
New-NetFirewallRule -DisplayName "SMI HTTP"  -Direction Inbound -Protocol TCP -LocalPort 80  -Action Allow
New-NetFirewallRule -DisplayName "SMI HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
New-NetFirewallRule -DisplayName "SMI RTP"   -Direction Inbound -Protocol UDP -LocalPort 10000-10199 -Action Allow
```

داخل اوبونتوی WSL — دقیقاً همان بخش ۳:

```bash
curl -fsSL https://get.docker.com | sh
unzip ~/Downloads/mini-voip-free-server-bundle-*.zip -d ~/mini-voip-free   # فایل را اول به ~/ کپی کنید
cd ~/mini-voip-free
sudo bash scripts/deploy/install-server.sh
```

بقیه‌ی مسیر (گرفتن APK با `server_ip` = دامنه‌ی همان ویندوز، نصب، تماس) عیناً بخش‌های ۴ تا ۶ است.

### ملاحظات صادقانه برای ویندوز

- **ویندوز ۱۰:** بدون mirrored networking فوروارد UDP به WSL راه استاندارد ندارد → تماس صوتی از اینترنت کار نخواهد کرد (فقط HTTPS). برای ویندوز ۱۰ همان VPS لینوکسی را توصیه می‌کنیم.
- **CGNAT / بدون فوروارد روتر:** هیچ تونلی در این مخزن برای RTP/UDP تعریف نشده؛ دامنه از اینترنت قابل‌دسترس نمی‌شود و Let's Encrypt هم گواهی نمی‌دهد → سرور روی VPS بالا بیاید.
- **فقط داخل LAN:** می‌شود ولی گواهی معتبر لازم است (اپ هرگز TLS را دور نمی‌زند)؛ راه فعلی مخزن فقط HTTP-01 است. اگر لازم شد، سوییچ Caddy به گواهی فایل‌محور (DNS-01) با یک تصمیم ثبت‌شده اضافه می‌شود.
- عملکرد WSL2 برای بیلد اول Asterisk (۱۵–۳۰ دقیقه) کافی است؛ برای بهره‌برداری پایدار چندکاربره، VPS/سرور لینوکسی مسیر رسمی است.
