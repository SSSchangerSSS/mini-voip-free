# 0012 — دامنه جدید تأییدشده کاربر، 2026-10-31

کاربر پس از تأیید کارکرد دو Android واقعی، صریحاً چهار تغییر خواست: دریافت در قفل/پس‌زمینه/فرایند بسته با بالاترین اولویت؛ اصلاح مسیر اولیه گوشی/بلندگو؛ فایل اجرایی CLI سرور؛ پنل تعریف داخلی با نام/شماره/رمز و فهرست نام/شماره در اپ و نمایش هویت تماس‌گیرنده.

این درخواست، استثنای ثبت‌شده بند خارج‌دامنه پنل و دفترچه داخلی در نسخه اولیه PROJECT_SPEC است. پنل فقط مدیریت داخلی همین شرکت در همان Control API است؛ سرویس تازه، ثبت‌نام عمومی یا CRM ایجاد نمی‌شود. دسترسی مدیریت با اعتبارنامه جدا، نشست HttpOnly و CSRF محافظت می‌شود؛ فهرست گوشی فقط نام/شماره داخلی فعال و فقط پس از احراز هویت است. هیچ رمز/secret در فهرست یا Git منتشر نمی‌شود. شماره‌های موجود و شناسه‌های wire ثابت می‌مانند. نام خالی به نمایش شماره برمی‌گردد؛ نام کارمندان جعل نمی‌شود.

Push واقعی به Firebase/کلیدهای واقعی و اجازه‌های سیستم/آزمون گوشی وابسته است. قبل از ورود اولیه و بعد از Android Force Stop، تضمین بیدارشدن داده نمی‌شود؛ نبود پیش‌نیاز با موفقیت ساختگی جایگزین نمی‌شود. تغییر وابستگی بومی فقط با pin و build واقعی ثبت می‌شود. تأیید قبلی کاربر درباره تماس foreground فقط evidence گزارش‌شده توسط کاربر است و خودکار پذیرش Push/قفل نیست.

پیاده‌سازی Android از `androidx.core:core-telecom:1.0.0` و `firebase-messaging:26.0.1` با pin دقیق استفاده می‌کند؛ دانلود وابستگی از Aliyun و build Release واقعی ثبت شده‌اند. Core-Telecom مالک یگانه مسیر صداست و AudioSwitch موازی WebRTC غیرفعال می‌شود. UI مسیر واقعی سیستم را نمایش می‌دهد؛ ترجیح شروع wired/Bluetooth/earpiece/speaker است. بدون earpiece، speaker آخرین خروجی معتبر است، نه دکمه خاموش جعلی.

مهاجرت افزایشی SQLite شماره 2 فقط DisplayName را به داخلی‌های موجود اضافه می‌کند. secret مدیریت جدا و اختیاری است؛ نبود آن پنل را بسته نگه می‌دارد. HTTP مدیریت فقط روی loopback با Host صریح محلی مجاز است، LAN به HTTPS نیاز دارد. API دفترچه فقط GET نام/شماره فعال است؛ عملیات provisioning زیر نشست و CSRF مدیریت قرار دارند.

اصلاحات واقعی FCM شامل RS256/RSA، رشته‌بودن همه مقادیر data، binding دقیق دستگاه/generation، مهلت UTC و پاک‌کردن فقط token/generation نامعتبر است. واحدهای جدید با کلید RSA موقت fixture اعتبار امضا را بررسی می‌کنند؛ این آزمون تحویل Firebase نیست. SDK بومی می‌تواند اعلان تماس را پیش از آماده‌شدن Flutter بسازد؛ تأیید cold delivery همچنان به پروژه واقعی و گوشی Google Play services نیاز دارد. مرجع نتیجه و محدودیت‌ها: `qa/reports/2026-10-31-phase2/REPORT.fa.md`.
