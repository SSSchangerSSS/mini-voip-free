# 0013 — دریافت Android بدون Google/Firebase، 2026-10-31

مالک صریحاً وابستگی به حساب Google را رد کرد. این تصمیم مسیر Android تصمیم 0012 را جایگزین می‌کند: هیچ پروژه، حساب، SDK یا پیکربندی Firebase برای Android این نسخه لازم نیست. ماژول اختیاری قدیمی FCM سمت سرور در مسیر اصلی استفاده نمی‌شود و فایل‌های خالی secrets فعال نمی‌شوند. iOS و انتشار فروشگاه موضوع این تحویل نیستند.

سرویس بومی `SmiIncomingService` با اعلان دائمی آماده‌باش، FlutterEngine/SIP موجود را زنده نگه می‌دارد؛ شبکه همان HTTPS/WSS خصوصی با CA و اعتبارسنجی قبلی است. SIP MESSAGE سرنخ سریع است؛ heartbeat بومی هر 5 ثانیه فقط API احرازشده تماس جاری را reconcile می‌کند تا از دست‌رفتن سرنخ مانع دریافت نشود. تلاش مجدد login/REGISTER در خطای موقت با guard و فاصله حداقل30ثانیه انجام می‌شود؛ خطای اعتبارنامه وارد حلقه ورود نمی‌شود. این استثنای لازم بخش polling محدود قبلی برای خواسته جدید مالک است؛ سرور یا پروتکل جدید ایجاد نشده است.

برای Android14+ آماده‌باش نوع `specialUse` با شرح کاربرد تماس داخلی دائمی دارد؛ نوع phoneCall فقط در طول تماس واقعی استفاده می‌شود. آماده‌باش dataSync نیست (محدودیت 6ساعت Android15) و phoneCall در زمان boot اجرا نمی‌شود. Boot/MyPackageReplaced در صورت وجود حساب ذخیره‌شده، سرویس آماده‌باش را آغاز می‌کند. START_STICKY برای بازیابی معمول سیستم است؛ stopWithTask=false با حذف Recent خاتمه نمی‌یابد. Force stop، توقف توسط مدیریت سرویس‌های سیستم و هر محدودیت سازنده نمی‌تواند با تضمین دور زده شود.

Partial wake lock و Wi-Fi lock فقط در طول آماده‌باش نگه داشته و هنگام توقف/خروج حساب آزاد می‌شوند؛ مصرف باتری این روش بیشتر از push ابری است. برای خواب طولانی، کاربر باید اجازه اعلان، full-screen در نسخه‌های مربوطه و معافیت باتری/Auto start سازنده را فعال کند. آیکون تنظیمات تماس فرم رسمی سیستم را باز می‌کند؛ معافیت خودسرانه اعطا نمی‌شود. آماده‌باش هیچ میکروفونی باز نمی‌کند؛ capture فقط پس از پاسخ کاربر شروع می‌شود.

اولین نصب باید یک بار باز و وارد حساب شود. دریافت بعد از reboot پس از بازشدن اولیه قفل و بازیابی شبکه باید آزمون شود. قطع Wi-Fi یعنی نبود دسترسی به سرور؛ اینترنت عمومی و Google Play services برای تماس داخل LAN لازم نیستند. صحت سخت‌افزار/صدای فیزیکی و محدودیت OEM فقط با آزمون همان گوشی تأیید می‌شود.

مراجع: https://developer.android.com/develop/background-work/services/fgs/service-types ، https://developer.android.com/about/versions/15/behavior-changes-15 ، https://developer.android.com/training/monitoring-device-state/doze-standby . نتایج واقعی در گزارش phase2 ثبت می‌شوند؛ build یا تست واحد جای آزمون گوشی را نمی‌گیرد.

پیش‌فرض STUN عمومی Google در sip_ua نیز صریحاً با فهرست ICE خالی برای نصب LAN جایگزین شد؛ اتصال host/peer-reflexive به PBX خصوصی آزمون می‌شود. دسترسی از اینترنت/NAT جداگانه در دامنه این تحویل نیست. Heartbeat تماس Connected را با deadline راه‌اندازی قطع نمی‌کند؛ تست رگرسیون عبور از دو دقیقه اضافه شد.

مشاهده قطع فرایند هنگام تعویض APK نشان داد یک server call باقی‌مانده نباید به‌عنوان تماس دارای media بازیابی شود. هنگام startup اگر سرور Connected برگرداند ولی SipAdapter هیچ call زنده‌ای ندارد، leg قبلی صریحاً پایان داده می‌شود و پیام تماس مجدد نشان داده می‌شود؛ تست رگرسیون جدا دارد. همچنین logSeverity بومی WebRTC پیش از ساخت رسانه روی none قرار گرفت؛ INFO بومی حاوی اعتبارنامه موقت ICE است و نباید منتشر شود. SIP logging قبلاً خاموش بود.

ثبت وضعیت آماده‌باش علاوه بر REGISTER به موفقیت Control API وابسته شد؛ قطع Control نباید با اعلان آماده سبز پنهان شود. تست رگرسیون آن اضافه شد. SDK بومی WebRTC150.7871.04 (همان نسخه transitive قبلی flutter_webrtc1.6.3) برای کنترل عمومی logging صریحاً direct شد؛ نسخه ارتقا نکرد. برای خاموش‌کردن debug native، آماده‌سازی logging پیش از تزریق LogSink Flutter انجام می‌شود. مدل گوشی شرط پیاده‌سازی نیست؛ هدف عمومیAndroid8–15 و آزمون نمونه8/15 است، نه ادعای مشاهده همه مدل‌ها یا نسخه‌های میانی.

در Android8 آزمایش screen-off در نمونه9 با اعلان موجود ولی بدون بیدارشدن صفحه FAIL شد. نمونه10 با wake lock صفحه حداکثر10ثانیه و Activity قفل فقط API26–28 اصلاح شد؛ در DND یا اعلان/کانال مسدود این fallback اجرا نمی‌شود. مسیر API29+ همچنان FSI سیستم است. پس از پایان native call نیز اجازه نمایش روی قفل پاک می‌شود.

دروازه امنیت لاگ هنوز FAIL است: SDK اطلاعات موقت ICE را در INFO می‌نویسد، حتی با تنظیمnone و کنترل runtime پیش ازSDP. نمونه15 ترتیب سه فراخوانی تنظیم و سپس وقوع لاگ را بدون ثبت raw credential نشان داد. گیت awaitSDP با49 تست Flutter بررسی شد، اما این تست اثبات حذف لاگ SDK نیست. SDK144 ناسازگار بود و rollback شد (0014). پچ سورس پیشنهادی در patches/webrtc آماده بررسی است؛ اعمال/ساخت آن NOT_RUN. تا رفع و آزمون باینری، CodeReady کامل/انتشار امن BLOCKED است.
