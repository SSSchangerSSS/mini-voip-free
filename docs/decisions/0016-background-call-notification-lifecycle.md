# 0016 — اصلاح چرخه اعلان تماس و دریافت پس از بستن رابط

تاریخ: 2026-11-01. مالک روی دو گوشی گزارش کرد تماس پس از بستن اپ دریافت نمی‌شود و بعد از پاسخ، زنگ ادامه دارد. دامنه Android8–15 و بدون Google حفظ می‌شود؛ موتور SIP، پروتکل و نسخه SDK تغییر نمی‌کنند.

نقص قطعی کد زنگ: اعلان FLAG_INSISTENT در همان ID به حالت silent تغییر می‌کرد؛ حذف صریح اعلانِ در حال پخش پیش از اعلان مکالمه انجام نمی‌شد. اعلان ورودی4101 هنگام قصد پاسخ/رد/پایان cancel و اعلان بی‌صدای مکالمه4102 در کانال کم‌اهمیت جدا نشان داده می‌شود. پاسخ از UI پیش از HTTP/SIP و پاسخ از اعلان پیش از ارسال event به Dart زنگ را ساکت می‌کند. latch بومی مانع برگشت زنگ با پیام دیرهنگام است.

برای دریافت پس‌زمینه، نمایش تماس به سرویس آماده‌باش foreground موجود منتقل شد؛ دیگر برای هر تماس، پیش از ثبت Core-Telecom، سرویس foreground دوم از پس‌زمینه شروع نمی‌شود. همان سرویس هنگام مکالمه type phoneCall را نیز دارد و پس از آن به آماده‌باش برمی‌گردد. بستن task فقط رابط را می‌بندد؛ callback آن heartbeat را فوراً می‌فرستد. بدون سرویس آماده‌باش، نمایش تماس موفق فرض نمی‌شود.

مجوز اعلان، مسدودنبودن کانال، معافیت باتری و زنده‌بودن سرویس از native بازخوانی می‌شوند؛ نبودشان اعلان آماده‌باش/صفحه را «آماده دریافت پس‌زمینه» نشان نمی‌دهد و دکمه تنظیمات واضح دارد. این تغییر دورزدن مجوز سیستم یا تضمین احیای Force stop نیست.

Baseline16 رویQA15 با Back اعلان صوتی4101 داشت؛ runner اول به‌اشتباه دنبال صفحه تمام‌صفحه هنگام unlocked بودن بود و FAIL شد. metadata NotificationManager وجود soundKey/vibrateKey را نشان داد؛ بنابراین ایراد گوشی مالک در این baseline بازتولید کامل نشده است و ادعای ریشه قطعی OEM نداریم. پس از اصلاح، Back، حذف task، screen-off و قطع زنگ پس از پاسخ باید با همان APK جدید بررسی شوند؛ نتیجه نهایی در گزارش مرحله ثبت می‌شود.

مرجع محدودیت foreground-service: https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start ؛ مرجع اعلان: https://developer.android.com/reference/android/app/Notification#FLAG_INSISTENT .

نتیجه نمونه18: FAIL با IllegalArgumentException هنگام ارسال اعلان CallStyle مکالمه از NotificationManager بدون foreground flag. Crash metadata در گزارش نگه داشته می‌شود. نمونه19 اعلان‌های4101/4102 را با startForeground روی همان سرویس آماده‌باش موجود جابه‌جا می‌کند؛ سپس ID قبلی cancel می‌شود. پایان تماس، اعلان4201 آماده‌باش را برمی‌گرداند و ID تماس پاک می‌شود. سرویس دوم و startForegroundService جدید در مسیر دریافت تماس وجود ندارد. نمونه18 منتشر نشد.

آزمون واقعی UI درنمونه19 دو کارت MiniVoIP درRecentها نشان داد؛ singleTop همراهtaskAffinityخالی می‌توانست از launcher و اعلان، taskهای جدا برای همان engine بسازد. نمونه20 ازsingleTask وaffinityپیش‌فرض برنامه استفاده می‌کند تا صفحه تماس و شماره‌گیر یک Activity/task داشته باشند. شناسه کانال، Actionها و حساب‌ها تغییر نمی‌کنند. این اصلاح پس از مشاهده واقعی چند کارت انجام شد؛ screenshot در شواهد محفوظ است.

نمونه21 علاوه برsingleTask، پس از ایجادActivity فقطtaskهای قدیمی متعلق به همین اپ را ازRecentها پاک می‌کند تا ارتقا ازsingleTop هم یک کارت داشته باشد. حساب/engine/اطلاعات سایر اپ‌ها پاک نمی‌شوند. APIشناسهtask برای26–28 و29+ جدا رعایت شده است. نمونه20 فقط build شد و انتشار عمومی نداشت.
